## CDN 方案调研（用户要求：免费服务，且**不处理原始素材**）
- **约束**：不转码、不重压缩、不动源图字节。所以 WebP/AVIF/pngquant 全部排除，
  只能做"原样搬运 + 分发层优化"。
- **体积实测**（`git/trees?recursive=1` 拿的 blob size，无需下载）：
  合计 19,443 文件 / **6,985.2 MB**。
  - `painting.png` 2,948 张 / **5,514.8 MB（79.0%）** / 平均 1,915 KB ← 唯一体积大头
  - `spine.skel` 2,120 / 579.9 MB（8.3%）、`spine.png` 2,121 / 503.7 MB（7.2%）
  - 图标三件套（shipicon+squareicon+equipicon）合计仅 179 MB（2.6%）
  - `painting.obj` 2,717 / 62.6 MB、`painting.json` 2,167 / 0.5 MB（图层元数据）
- **R2 免费额度**（developers.cloudflare.com/r2/pricing）：10 GB-month 存储、
  100 万 Class A、1000 万 Class B、**egress 永久免费**。
  → 6.82 GB 占 68%，余量 3.18 GB。按约 0.5~0.6 GB/年新增，可撑约 5 年；
  超出部分 $0.015/GB-month，不是悬崖。
- **Pages 不能用**：免费版 **20,000 文件/站**（付费才是 100,000），
  我们 19,443 已占 97%，一次热更就超。只能托管前端，图片必须走 R2。
- 生产访问必须绑**自定义域**；`r2.dev` 子域有速率限制，仅供开发。
- 结论：原样全量放 R2 即可，不需要为了省空间动素材。

## R2 自动推送方案调研（2026-10-21 晚）
- **两个阻断性缺口**（实测发现，写 workflow 前必须处理）：
  1. **spine 不在 `azl_assets.py` 能力内**：代码里 grep `spine` 零命中，`CATEGORY_LIST`
     只有 13 类，无 spine。`AUTOMATION.md:39/666` 自己写了"spine（小人动画）你手工整 ❌ 还没做"。
     但 `HANDOFF.md:247` 说"已支持 --items … spine" —— **这句是错的**。
     spine 有 2,121 目录 / 6,363 文件 / **1,083 MB（15.4%）**，无法自动生成。
  2. **`requirements.txt` 缺 `opencv-python`**：`azl_assets.py` 顶部 `import cv2`，
     但依赖清单只有 UnityPy + ljd，CI 里会直接 ImportError。
- **无域名时的公开访问**：`pub-<bucketid>.r2.dev` 可用但官方定性"非生产"，几百 req/s 会 429、
  带宽可能被限、不能配缓存规则。URL 绑桶固定不变，以后换域名只改 `VITE_CDN`。
- **R2 上传不要用 REST API**（限 1200 请求/5 分钟），必须走 S3 兼容 API。
- **本机工具缺失**：rclone / aws-cli / boto3 都没有，需要装。
- `azl_assets.py` 现成机制：`--state .azl/assets-state.json`（增量判据）、
  `--report-files`（写 NUL 分隔清单，仓库相对路径 `public/...`）、`--seed`（只补 state 记录）。
  `--items` 默认只有 painting+squareicon+shipicon；`--scope` 默认 `used`（按 public/data 引用裁）。
